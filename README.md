# ProxyGPT

Настоящий **claude.ai** и **chatgpt.com** через ваш сервер, без VPN и без приложений.

Вы ставите на свой сервер за границей одну команду, а на устройствах один раз включаете свой DNS. После этого браузеры и официальные приложения Claude и ChatGPT ходят на эти сайты через сервер, а весь остальной интернет - напрямую, как раньше.

- Сайт открывается на своём **настоящем адресе** и с его сертификатом. Поэтому работают вход в аккаунт, проверки «вы не робот», ключи доступа, подписка.
- Сайт видит адрес и страну **сервера**.
- Сервер **ничего не расшифровывает**: он пересылает зашифрованное соединение как есть и переписку не видит.
- Через сервер идут **только сайты из списка**. Всё остальное идёт напрямую, скорость интернета не меняется.

## Как это работает

```
устройство ──DNS-запрос (зашифрован, DoH/DoT)──> ваш DNS: «claude.ai = IP сервера»
устройство ──TLS до claude.ai──> сервер:443 (SNI-прокси, без расшифровки) ──> claude.ai
устройство ──всё остальное──> напрямую
```

На сервере работают два контейнера:

| Контейнер | Что делает |
|---|---|
| `proxygpt-nginx` | SNI-прокси на порту 443: по имени сайта в начале соединения пересылает его настоящему сайту. Пропускает только сайты из списка, остальные соединения закрывает. Ещё отдаёт страницу настройки и профиль DNS |
| `proxygpt-dns` | ваш DNS (CoreDNS): DoT на порту 853 и DoH через 443. Для сайтов из списка отвечает IP сервера, для остальных - обычным ответом через Cloudflare DNS |

## Что нужно

1. **Сервер за границей**, с которого открываются нужные сайты: Debian 12/13 или Ubuntu 22.04/24.04, 1 ГБ памяти, доступ root.
2. **Свободные порты 443 и 853**, а при выпуске сертификата ещё и **80**. Если на сервере уже есть сайты на 443, нужен другой сервер или отдельный IP.
3. **Имя для DNS-сервера** в вашем домене, например `dns.example.com`. Его нужно настроить **до установки**, см. шаг 1.

## Установка

### Шаг 1. Направить имя на сервер (до установки)

Сначала создайте в DNS вашего домена запись, которая указывает на IP сервера. Без неё установка остановится: скрипт проверяет имя и выпускает на него сертификат.

| Поле | Значение |
|---|---|
| Тип | `A` |
| Имя | `dns` (получится `dns.example.com`; можно любое своё) |
| Значение (IPv4) | IP вашего сервера |
| В Cloudflare | **серое облако, DNS only** - с оранжевым трафик пойдёт через Cloudflare, его адреса в России режутся, и сертификат не выпустится |
| TTL | Auto |

Записи `AAAA` (IPv6) для этого имени не делайте, если на сервере нет IPv6.

Имя может содержать буквы, цифры и дефис. **Подчёркивание нельзя** (`dns_alex` не подойдёт, `dns-alex` подойдёт): Let's Encrypt не выпускает сертификаты на такие имена.

Проверьте, что запись уже видна (обычно через 1-5 минут). Должен вернуться IP сервера:

```bash
dig +short dns.example.com @1.1.1.1
```

На Windows: `nslookup dns.example.com 1.1.1.1`. Если пусто или другой адрес, подождите и проверьте ещё раз.

### Шаг 2. Установка одной командой

На сервере, от root:

```bash
curl -fsSL https://raw.githubusercontent.com/itnos/ProxyGPT/main/install.sh | bash -s -- --domain dns.example.com --agree-tos --relay
```

Если на сервере нет `curl`, то же самое через `wget`:

```bash
wget -qO- https://raw.githubusercontent.com/itnos/ProxyGPT/main/install.sh | bash -s -- --domain dns.example.com --agree-tos --relay
```

Вместо `dns.example.com` укажите имя из шага 1. `--agree-tos` - согласие с [условиями Let's Encrypt](https://letsencrypt.org/repository/): скрипт выпускает бесплатный сертификат для DNS-сервера.

`--relay` сразу ставит **приёмник** - он нужен, чтобы Claude и ChatGPT шли через ваш сервер и тогда, когда на телефоне включён другой VPN (см. [Если на устройстве включён VPN](#если-на-устройстве-включён-vpn)). Заранее не знаешь, понадобится ли, а места и сил он почти не требует, поэтому он включён в команду. Не нужен - уберите `--relay` (или выключите потом командой с `--no-relay`); понадобится позже - запустите ту же команду с `--relay`, переустанавливать ничего не придётся.

Скрипт сам:
- поставит Docker, Docker Compose и certbot, если их нет;
- проверит, что имя указывает на этот сервер и порты свободны;
- выпустит сертификат и настроит его продление;
- соберёт настройки, запустит контейнеры и проверит, что DNS и прокси отвечают;
- напечатает **секретную ссылку на страницу настройки устройств** вида `https://dns.example.com/<секрет>/`.

Все секретные ссылки (страница устройств, страница подписки Happ, ключ приёмника) скрипт хранит на сервере в одном файле `/opt/proxygpt/links.txt` (читать может только root). Посмотреть с компьютера:

```bash
ssh root@<IP сервера> cat /opt/proxygpt/links.txt
```

Ссылки **не меняются** при повторных запусках установки: секреты хранятся в `/opt/proxygpt/settings.env`. Корень `https://dns.example.com/` без секрета отвечает 404, открыт только адрес DNS-запросов `/dns-query`, его используют устройства.

Дополнительные параметры:

| Параметр | Что делает |
|---|---|
| `--email you@example.com` | почта для писем Let's Encrypt (по умолчанию без почты) |
| `--sites "claude.ai anthropic.com"` | свой список сайтов вместо стандартного |
| `--ip 203.0.113.10` | внешний IP, если сервер за NAT и IP не определился сам |
| `--relay` | приёмник для работы через другой VPN (уже в команде выше); `--no-relay` - выключить |
| `--check` | только проверить, что всё работает (см. ниже) |
| `--uninstall` | удалить всё, кроме сертификата |

## Настройка устройств

Проще всего открыть на устройстве **секретную ссылку на страницу настройки**, которую напечатала установка (`https://dns.example.com/<секрет>/`, она же в `links.txt`): там все инструкции с вашими адресами и кнопкой профиля. То же самое коротко (`<секрет>` - из вашей ссылки):

### iPhone и iPad

1. В **Safari** откройте `https://dns.example.com/<секрет>/apple.mobileconfig` (кнопка «Скачать профиль DNS» на странице настройки), нажмите «Разрешить».
2. Настройки → вверху «Профиль загружен» → **Установить**.
3. Проверка: Настройки → Основные → VPN и управление устройством → DNS → выбран «ProxyGPT DNS».

Удалить: Настройки → Основные → VPN и управление устройством → профиль → Удалить.

### Mac

```bash
curl -fsSL https://dns.example.com/<секрет>/apple.mobileconfig -o ~/Downloads/proxygpt-dns.mobileconfig && open ~/Downloads/proxygpt-dns.mobileconfig
```

Затем Системные настройки → Основные → **Управление устройством** (или поиск «Профили») → «ProxyGPT DNS» → Установить.

### Android 9 и новее

Настройки → Сеть и интернет → **Частный DNS** (на Samsung: Подключения → Другие настройки → Частный DNS) → «Имя хоста поставщика частного DNS»:

```
dns.example.com
```

### Windows 11

PowerShell **от имени администратора**:

```powershell
irm https://dns.example.com/<секрет>/windows.ps1 | iex
```

Скрипт добавляет ваш DNS-сервер с шифрованием (DoH) и ставит его на все активные подключения. Вернуть как было:

```powershell
Get-NetAdapter | % { Set-DnsClientServerAddress -InterfaceIndex $_.ifIndex -ResetServerAddresses }
```

### Linux (systemd-resolved)

```bash
sudo mkdir -p /etc/systemd/resolved.conf.d && printf '[Resolve]\nDNS=203.0.113.10#dns.example.com\nDNSOverTLS=yes\n' | sudo tee /etc/systemd/resolved.conf.d/proxygpt.conf && sudo systemctl restart systemd-resolved
```

Вместо `203.0.113.10` - IP сервера.

## Если на устройстве включён VPN

**Пока на устройстве включён VPN, система отдаёт ему весь трафик и DNS**, а профиль DNS не действует. Так устроены iOS, macOS, Android и Windows, и настройкой DNS это не перебить. Поэтому при включённом VPN Claude идёт через сервер VPN, с его адресом.

Если нужно, чтобы **при включённом VPN Claude и ChatGPT шли через VPN, а в интернет выходили с вашего сервера**, включите приёмник:

```
телефон → VPN (как обычно, с его обходом блокировок) → приёмник на вашем сервере → Claude
телефон → VPN → всё остальное
```

Для этого нужен VPN-сервис с подпиской в формате Xray JSON и приложение **Happ** (на iPhone, Android, Mac). Подписки для Happ отдают многие сервисы на Xray (VLESS, Reality).

### 1. Приёмник на сервере

Если ставили командой из раздела [Установка](#установка), приёмник **уже включён** - переходите к шагу 2. Если ставили без `--relay`, включите его той же командой, переустанавливать ничего не нужно:

```bash
curl -fsSL https://raw.githubusercontent.com/itnos/ProxyGPT/main/install.sh | bash -s -- --relay
```

Приёмник (Xray, VLESS через WebSocket) стоит за тем же адресом, что страница DNS: `https://dns.example.com/<секретный путь>`. Для VPN это обычное HTTPS-соединение к вашему DNS-серверу, поэтому его пропускают даже серверы VPN, которые особо обрабатывают Claude по имени. Выпускает приёмник только сайты из `sites.txt`, остальные закрыты.

В конце установки скрипт печатает **ссылку на страницу подписки Happ**:

```
Работа через другой VPN (приёмник включён). Страница подписки Happ - откройте на телефоне,
вставьте ссылку подписки своего VPN и нажмите «Добавить в Happ»:

  https://dns.example.com/happ/3f9c…/
```

**Это секрет**: по ссылке можно ходить через ваш сервер. Не публикуйте её и не оставляйте на скриншотах.

Где её найти потом. Скрипт хранит ссылки на сервере в файле `/opt/proxygpt/links.txt` (читать может только root). Для этого способа в нём:
- `https://dns.example.com/happ/<секрет>/` - страница подписки Happ;
- `vless://…` - ссылка самого приёмника для ручной настройки клиентов Xray и для `tools/happ_relay.py`.

Посмотреть с компьютера:

```bash
ssh root@<IP сервера> cat /opt/proxygpt/links.txt
```

Ссылка **не меняется** при повторных запусках установки (обновление, правка `sites.txt`, `--check`): секреты хранятся в `/opt/proxygpt/settings.env`. Новая появится только после `--uninstall` и установки заново или если сменить её специально (например, если ссылка попала к чужим людям):

```bash
sed -i '/^PG_SUB_TOKEN=/d' /opt/proxygpt/settings.env       # новая страница подписки
sed -i '/^PG_RELAY_UUID=/d; /^PG_RELAY_PATH=/d' /opt/proxygpt/settings.env   # новый ключ приёмника
```

и снова запустить команду установки. После смены старая ссылка перестаёт работать: подписку в Happ нужно добавить заново со страницы.

### 2. Подписка для Happ

Откройте на телефоне **страницу подписки** - ссылку, которую напечатала установка (или из `/opt/proxygpt/links.txt`, см. выше):

1. Вставьте ссылку подписки своего VPN (ту, что открывается в Happ).
2. Нажмите **«Добавить в Happ»**. Если приложение не открылось - «Скопировать ссылку», затем в Happ «+» → «Вставить из буфера».
3. Выберите любой профиль с пометкой «· мой сервер» и подключитесь. Родное приложение VPN выключите: одновременно работает только один VPN.

Это своя подписка на вашем сервере: при каждом обновлении в Happ (раз в 6 часов и вручную) сервер берёт **свежие профили VPN** как есть - серверы, обход белых списков, автовыбор, их правила - и добавляет в каждый только одно: сайты из списка идут в приёмник, а само подключение к приёмнику идёт **через автовыбор этого же VPN**. Поэтому оно работает в той же сети, где работает VPN, в том числе на мобильном интернете с белыми списками. Ссылку VPN сервер не хранит: она живёт только внутри ссылки подписки в Happ.

Проверка: `claude.ai/cdn-cgi/trace` и `chatgpt.com/cdn-cgi/trace` показывают `ip=` вашего сервера, а `cloudflare.com/cdn-cgi/trace` - адрес сервера VPN.

**Без страницы**, файлом на компьютере (из папки репозитория):

```bash
python3 tools/happ_relay.py --sub "https://ссылка-подписки-вашего-VPN" --relay "vless://...из links.txt" -o happ-profiles.json
```

Затем откройте файл на телефоне, скопируйте весь текст, Happ → «+» → «Импорт из буфера обмена». Такой файл - снимок подписки: если VPN-сервис сменит серверы, соберите его заново.

**Секреты.** Страница подписки, ссылка подписки, `links.txt` и файл профилей открывают путь через ваш сервер, а ссылка подписки ещё и содержит ссылку вашего VPN. Не пересылайте их. Приёмник в любом случае выпускает только сайты из `sites.txt`.

## Список сайтов

Список лежит в `/opt/proxygpt/sites.txt`: один корневой домен в строке, поддомены входят сами. По умолчанию в нём:

```
claude.ai  claude.com  anthropic.com  claudeusercontent.com
chatgpt.com  openai.com  oaistatic.com  oaiusercontent.com
```

После правки запустите ту же команду установки ещё раз, можно без параметров: она пересоберёт настройки и перезапустит контейнеры. Новые домены сайта можно найти в браузере: DevTools (F12) → Network → столбец Domain.

## Насколько это скрыто от провайдера

| Что | Видит ли провайдер |
|---|---|
| Какие сайты вы спрашиваете у DNS | **нет**, запросы зашифрованы (DoH/DoT) |
| Что вы пользуетесь DNS-сервером | DoH выглядит как обычный HTTPS к `dns.example.com`. DoT на порту 853 узнаётся по номеру порта, но содержимое не видно |
| Подключение к сайту через сервер | IP сервера и **имя сайта** (`claude.ai`) в начале соединения |

Отсюда главное ограничение: **если провайдер режет сайт по имени, этот способ на его сети не сработает.** Шифрование DNS тут не помогает, имя видно в самом соединении. В мобильных сетях блокировки бывают жёстче, чем в домашних.

## Проверка, что всё работает

### На сервере

Та же команда, что для установки, с параметром `--check`:

```bash
curl -fsSL https://raw.githubusercontent.com/itnos/ProxyGPT/main/install.sh | bash -s -- --check
```

Она проверяет контейнеры, DoT (порт 853, для Android), ответ DNS по каждому сайту из списка, что обычные сайты идут напрямую, что сайт видит адрес сервера, и срок сертификата. Пример:

```
==> Проверка (dns.example.com, сервер 203.0.113.10)
  ✓ контейнер proxygpt-nginx работает
  ✓ контейнер proxygpt-dns работает
  ✓ DoT (порт 853, Android): отвечает, сертификат действителен
  ✓ DNS: chatgpt.com -> 203.0.113.10 (через сервер)
  ✓ DNS: claude.ai -> 203.0.113.10 (через сервер)
  ✓ DNS: example.com -> 93.184.215.14 (напрямую, как и должно)
  ✓ claude.ai видит адрес сервера: ip=203.0.113.10 loc=NL
  ✓ страница устройств открывается по секретному адресу (адрес - в links.txt)
  ✓ без секрета страница закрыта (https://dns.example.com/ - 404)
  ✓ приёмник: claude.ai через wss://dns.example.com выходит с адреса сервера   (если включён --relay)
  ✓ приёмник: сайты не из списка не пропускает
  ✓ страница подписки Happ отвечает (адрес - в links.txt)
  ✓ без секретного адреса страница подписки закрыта
  ✓ сертификат действует ещё 89 дн. (продлевается сам)
==> Всё работает.
```

Такая же проверка запускается сама в конце каждой установки.

### На устройстве

**Выключите VPN**, если он включён, и откройте в браузере на настроенном устройстве:

| Адрес | Что должно быть | Что это значит |
|---|---|---|
| `https://claude.ai/cdn-cgi/trace` | `ip=` **IP сервера**, `loc=` страна сервера | Claude идёт через сервер |
| `https://chatgpt.com/cdn-cgi/trace` | то же | ChatGPT идёт через сервер |
| `https://www.cloudflare.com/cdn-cgi/trace` | `ip=` **ваш обычный IP** | остальные сайты идут напрямую |

Как понять результат:
- В первых двух адресах ваш обычный IP: DNS на устройстве не применился, см. [Если не работает](#если-не-работает).
- Везде IP сервера: включён VPN. Скорее всего, через этот же сервер, и он перекрывает проверку.

Из командной строки:

| Система | Команда | Ожидается |
|---|---|---|
| Mac, Linux | `curl -s https://claude.ai/cdn-cgi/trace \| grep -E '^(ip\|loc)='` | `ip=` IP сервера |
| Windows | `Resolve-DnsName claude.ai -Type A` | `IPAddress` = IP сервера |
| любая | `curl -s -o /dev/null -w '%{remote_ip}\n' --doh-url https://dns.example.com/dns-query https://claude.ai/` | IP сервера (проверка самого DNS-сервера, без настройки устройства) |

На секретной странице настройки (`https://dns.example.com/<секрет>/`) есть тот же раздел «Проверка», уже с вашими адресами.

## Остановка и запуск

Команды - та же команда установки с параметром (на сервере, от root). Ниже для краткости `INSTALL` - это начало команды:

```bash
curl -fsSL https://raw.githubusercontent.com/itnos/ProxyGPT/main/install.sh | bash -s --
```

| Команда | Что делает |
|---|---|
| `INSTALL --status` | что запущено, что остановлено, включён ли прокси сайтов |
| `INSTALL --stop dns` | **остановить DNS** - DoT (853) и DoH перестают отвечать. Так можно проверить, что будет с устройствами, если DNS-сервер недоступен |
| `INSTALL --start dns` | запустить DNS обратно |
| `INSTALL --stop proxy` | **выключить прокси сайтов**: DNS продолжает работать, но для Claude и ChatGPT отдаёт их настоящие адреса - сайты идут с устройств напрямую, сервер их больше не пересылает |
| `INSTALL --start proxy` | снова пускать сайты из `sites.txt` через сервер |
| `INSTALL --stop relay` | остановить приёмник и страницу подписки Happ (работа через другой VPN) |
| `INSTALL --start relay` | запустить их обратно |
| `INSTALL --stop` | **остановить всё** (`--stop all`): DNS, прокси, страницы, приёмник - как будто сервер недоступен |
| `INSTALL --start` | запустить всё (`--start all`) |

Пример вывода `--status`:

```
==> ProxyGPT: dns.example.com (203.0.113.10)
  ✓ работает   proxygpt-nginx  прокси сайтов, страницы, DoH на 443
  ■ ОСТАНОВЛЕН  proxygpt-dns    DNS: DoT 853 и DoH
  ✓ работает   proxygpt-relay  приёмник (работа через другой VPN)
  ✓ работает   proxygpt-sub    страница и подписка Happ
  прокси сайтов:  включён - сайты из sites.txt идут через сервер
```

**Что будет на устройствах, если DNS остановлен** (`--stop dns` или `--stop`):

| Устройство | Пока DNS остановлен | После `--start dns` |
|---|---|---|
| **iPhone, Mac** (профиль DNS) | в профиле запрещён уход на DNS сети (`AllowFailover = false`, iOS/macOS 26+): как на Android, сайты перестают находиться, Claude и ChatGPT **не идут напрямую**. Профиль, скачанный до 27.11.2026, этого запрета не содержит - с ним устройство уходит на DNS сети (роутер, оператор) и Claude идёт напрямую; переустановите профиль | возвращается сам; если устройство успело уйти на DNS сети - см. ниже |
| **Android** (частный DNS) | интернет пропадает: «Частный DNS-сервер недоступен» | возвращается сам |
| **Windows** (после `windows.ps1`) | сайты перестают открываться: запасного DNS нет | возвращается сам |
| **с включённым VPN** | DNS идёт через VPN: всё работает, кроме Claude и ChatGPT через приёмник, если остановлено всё (`--stop`) | возвращается сам |

Как вернуть iPhone и Mac на ваш DNS сразу после `--start dns`:
- **iPhone:** включить и выключить авиарежим (или Wi-Fi);
- **Mac:** выключить и включить Wi-Fi или сбросить кэш DNS: `sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder`;
- закрыть и снова открыть приложение Claude или ChatGPT: они помнят старые адреса и соединения.

Проверка: `claude.ai/cdn-cgi/trace` снова показывает `ip=` вашего сервера.

Вернуть интернет на Android или Windows, если сервер долго недоступен: выключить частный DNS («Автоматически») или на Windows вернуть DNS по умолчанию командой из раздела [Windows 11](#windows-11).

Остановленное не запустится само после перезагрузки сервера; повторный запуск установки запускает всё снова. Режим `--stop proxy` сохраняется и при перезагрузке, и при повторной установке, пока не будет `--start proxy`. Устройства помнят адреса несколько минут, поэтому после `--stop proxy` / `--start proxy` изменения на них видны не сразу.

## Если не работает

- **iPhone и Mac, Safari:** выключите «Частный узел iCloud» (Private Relay), он обходит DNS.
- **Chrome:** Настройки → Конфиденциальность и безопасность → Безопасный DNS → «Использовать текущего поставщика».
- **Включённый VPN** подменяет DNS: выключите его, пока пользуетесь этим способом.
- После настройки закройте и снова откройте браузер или приложение: они помнят старые адреса.
- **Android и порт 853:** если в какой-то сети частный DNS не подключается, там закрыт порт 853 (DoT). В такой сети это не обойти, на Android нет DoH в системных настройках.

## Риски

- **Правила сервисов.** OpenAI и Anthropic запрещают пользоваться сервисами из неподдерживаемых стран и блокируют аккаунты. Сервер скрывает ваш IP, но аккаунт могут заблокировать по другим признакам (карта, телефон). Это ваш риск.
- **Доступ к серверу.** DNS и прокси доступны всем, кто знает имя сервера. Прокси пускает только сайты из списка, но посторонние могут пользоваться ими через ваш сервер. Не публикуйте имя своего DNS-сервера.
- **Доверие.** Ставьте только на свой сервер. Переписку сервер не видит, но через него идут ваши соединения с этими сайтами.
